## 1. 范围与决定的层次

本稿让产品与架构评审者能够决定是否在 P2/V1.5+ 建设企业工作记忆。推荐先验证**员工明确提交的任务结果/Artifact**：减少重复排障与整理，输出带来源的候选；个人偏好是可选的窄场景，Workspace 经验共享必须经过显式授权。提交可以是批准客户端提供的“提交本次结果”动作，不要求员工重新撰写知识；不需要 EAP 执行任务或拥有通用 Runtime。

已接受的上位约束来自 [PRD P6/P7、§6.8、§10](../01-PRD.md)、[System Architecture §12/§13](../03-System-Architecture.md)、[CLI ADR-0010](0010-eap-cli-v1.md) 与 [Skill ADR-0015](0015-skill-registry.md)。PRD 将企业 Memory 放在 P2/V1.5+，Architecture 的 V2 展望不是本轮实施授权；[开发计划](../02-Development-Plan.md)也明确 Artifact/Knowledge Candidate 不阻塞 V1。本稿所有新增对象、状态、默认值、角色与恢复要求均为提案；设计卡完成不等于它们已接受或已实现。

不修改 PRD、任务优先级、现行协议或存储。没有生产代码、DDL、新服务部署、Portal 页面、自动全量会话回写、自动 Prompt 注入或已批准的实施卡。ADR-0029/0030 的候选检索/撤销执行细节不作为依赖：本稿只表达上位产品与安全不变量；后续实现前必须对齐届时**已接受**的全平台撤销和 Knowledge 契约，不能在 Memory 内另定义更弱的在途完成点。

## 3. 所有权映射与权威存储

| 对象 | EAP 提案语义 | 明确不等价的上游对象 |
| --- | --- | --- |
| Principal | 服务端验证的员工身份；共享对象另有 Workspace 管理者；离职用户不可继续消费自己的旧记忆 | body `user_id`、任意模型生成的 owner |
| Workspace | 每条记忆唯一所属的安全边界；无 Workspace 就拒绝 | `team_id` 字符串或本地目录 |
| Client | 调用客户端类型/注册上下文，例如 Codex、Harness；仅作来源与策略维度 | 上游 `agent_id`，也不是员工身份 |
| Agent 实例 | 可选的服务器登记实例引用，绑定 Workspace、发起 Principal 与客户端上下文；外部运行 ID 只作不可信关联标签 | ClientID；同一客户端的所有进程；新的自主 Principal |
| 个人记忆 | `(Workspace, owner Principal)`；可额外限制实例，不能因实例更换或 L2/L3 聚合变共享 | 跨 Workspace 的员工全局 profile |
| 共享工作经验 | Workspace 负责的显式共享对象；记录贡献者、授权者、目标 ACL 和用途 | team 内所有人默认可读的 L2/L3 |

实例终止不改变员工身份，也不自动转移记忆；相同 ClientID 的另一个员工不能读取。所有客户端身份字段只用于选择/关联，Gateway 必须从现有 Session 建立并验证权限，服务间只接受 audience 明确的短期身份，`agk_*` 不出入口，凭据不写进记忆。

拟把 Working Memory 的元数据、ACL、来源版本、有效期、审核与不可召回标记归属 EAP 现有 PostgreSQL 权威边界；原件需要存储时归现有 Artifact/Knowledge 的对象存储所有者，不复制成 MemoryCore 的第二份资产目录。此处是归属决定候选，不是表设计。索引、向量、摘要、缓存、scene/profile 文件均为可重建派生物，不能自行授权。

EAP 中的分层仅描述加工深度，不描述权限/可信级别：L0 是**显式提交且版本固定的材料**（可为引用，不默认复制 Conversation）；L1 是带证据片段的原子结论；L2 是同一可见性域内工作经验汇总；L3 是同域内稳定偏好摘要。任何 L1–L3 都是 Working Memory，不因层数而成为 Canonical、系统指令或 Skill。

Knowledge Candidate 是现有知识治理链的候选对象/引用，不在 Memory 新建正式知识库。发布后 Memory 保存 Canonical 的版本引用与晋升回执，不再维护独立的正式副本。Skill 候选必须走独立的 Registry 提交、服务端扫描、审核、签名、发布链；Knowledge 审核不等于允许脚本或安装包，Memory 无权签名或替客户端执行代码。

## 4. 来源、授权、TTL 和冲突

每个对象至少需要可审阅的概念字段（非 DDL）：对象/修订 ID、Workspace、owner/贡献者、可见性和用途、来源对象 ID+不可变版本+片段/摘要、直接父节点和传递来源集合、提取器/prompt/model 版本、创建 trace、分类、有效期、状态、审核目标版本/内容摘要/目标 ACL、幂等提交 ID。源版本与来源引用由服务端核验；模型伪造、缺失或越权的引用令输出隔离待修，不成为可召回结果。

**召回条件**是当前 Session 授权、对象可见性、每一个仍参与该修订的来源当前授权、未撤销/删除、未过期、策略/DLP 和可靠审计都通过。多源聚合取权限交集及最早到期，不取 ACL 并集；私人材料不得因和公开材料混合而共享。候选列表、计数、摘要、错误、引用与内容使用同样边界。无法解析来源、权限服务故障或检查不全均 fail closed，后台作业与重试也相同。

拟定生命周期：

`submitted → quarantined/validated → working → candidate → reviewing → approved → canonical-reference`

其中 validated 到 working 需要入库扫描与来源校验；candidate 到 reviewing 需要去重、冲突、可信度与敏感检查；approved 绑定不可变版本与明确目标 ACL；发布时重验审批者现有权限、全部来源与内容版本，再由 Knowledge 权威发布。拒绝为 `rejected`，修改产生新修订并使旧审批失效；任何状态均可进入 `expired / revoked / deletion-pending → purged`。审批超时/拒绝不发布，重试不把“批准已记录”当成“发布已完成”。发布结果未知时按同一操作 ID 查询权威回执，不重复创建 Canonical。

审核者拟为 Workspace 明确授予知识发布权限的人类，不能由候选内容、模型置信度、投稿者默认决定；默认要求与投稿者分离。共享晋升不能绕过来源 ACL：目标成员须都有源读取权，或由具有**源资料共享授权**的人显式改变源 ACL 并重做审核。仅批准知识发布不自动授予源共享权。若希望发布脱敏独立成果并切断来源撤销，这是额外产品与合规决定，本稿不允许。

去重仅在同 Workspace、相同可见性/owner 与兼容生命周期内匹配；同内容但不同来源不能丢掉 lineage。精确重复可返回原操作结果，语义相似只建议合并；合并新修订继承全部证据与最严格约束。冲突保留竞争修订和来源，个人偏好由本人明确选择，共享结论由审核者处理；不做“最后写入必胜”或让模型覆盖 Canonical。来源更新使依赖旧版本的派生物先停用，重算形成新修订；冲突检查不可用则候选停留待检查。

TTL 提案默认值（产品未决定）：显式输入引用/工作结论 30 天，候选审核 30 天，个人偏好 90 天；L2/L3 不得超过所有输入最早期限。读取、模型重算和重试不续期，用户显式续期仍须来源有效且审计；没有有效期的来源不意味着私人摘要永久保留。Canonical 使用 Knowledge 审核批准的有效期，并保留来源依赖；工作输入若是它的唯一证据，到期同样使其停用。发布时应先确认可持续的受治理源版本及留存期限，不能靠晋升偷偷延长个人材料保留。

## 5. 撤销、删除与出站责任

删除/TTL/源权限收窄先在权威边界使受影响对象与传递派生物**不可召回、不可再出站、不可发布**，再异步物理清理。在途内容释放和外部调用也必须遵守全平台即时撤销契约；只查请求开始时的成员资格不满足本提案。已被合法发送到客户端/外部模型的内容无法追回，不把停止后续释放描述为抹除历史披露。

- 源删除：停用所有引用该源修订的 L1/L2/L3、候选、Canonical 修订、引用预览、向量/关键词索引及缓存；多源混合先整体停用，只有从剩余合法源重新生成、校验并按需要重新审批的新修订才可见，不能文本删几句后直接恢复。
- 成员撤销：被移除者立即失去该 Workspace 的所有召回权；其个人记忆及由这些私有源派生的各层对象对任何人停用。已显式转归 Workspace 管理、来源独立合法且获批的共享知识可由其他当前成员继续读取；不能只靠“创建者已离开”自动销毁企业资料，也不能借此保留私人 profile。此差异须有共享转归的证据。
- 员工离职：身份失效先阻止全部 Workspace 访问，再按同样规则处理私人资料；共享资产管理员可接管维护责任，不自动取得私人内容。客户设备残留和已下载 Skill 按既有治理能力处理，不承诺远程擦除。
- 共享权限收窄：被排除者不能读取共享对象或任一派生摘要；其他仍获所有源授权者可读。ACL 混合物需重算，不能沿用旧宽 ACL。不存在绕过撤销的“缓存命中”路径。
- 清理与恢复：删除标记/撤销事实先于任何可见性恢复；队列消息、模型迟到输出、重试、备份恢复和索引重建在提交前重验来源修订与删除状态。旧作业只能取消或丢弃，不能 upsert 复活。物理清理失败保持 deny，记录 pending/failed、重试次数、最老积压和告警；幂等重试直到清理完成。备份恢复必须先重放撤销/删除事实再开放读流量。物理删除 SLA、备份到期和法定留存由产品/数据治理确定；保留义务不授予业务召回权。

责任边界：Gateway/既有身份与 Policy 负责当前调用授权；拟议 Memory 领域负责 lineage、可见性、期限和修订；Knowledge 负责正式发布与来源依赖撤销；后台提取仅持受限服务权限和原始发起者/来源上下文，不能借服务身份提升权力。模型 egress 使用既有受治理 LLM 路径，入库扫描之外每次发送前重做 Policy/DLP；local-only、redact、approval、deny 均须落实，缺少审批续接就阻断，不退到直连 Provider。

提示注入防护：来源和记忆始终置于不可信数据位置，不作为 system/developer 指令。提取只返回受约束结构和证据，不启用网络、任意文件/工具执行；输出 schema、来源、长度和分类由服务器验证。内容中的“忽略策略/改 owner/发布 Skill”不产生授权。召回先明确展示来源、修订、有效期和工作态标签，自动注入另待产品决定；输出扫描不能代替权限检查。

审计沿用可靠安全审计路径，记录 actor/Workspace、动作、对象版本/来源标识、策略结果、trace、审批与恢复结果；不记录原文、完整对话、prompt 或密钥。入库/发布等授权状态变更与审计必须有可恢复的一致性；审计不能持久化时不得成功激活或释放内容。撤销禁止恢复到 allow，审计故障要可观测并可靠补偿，不能因记录失败撤销 deny。模型用量/成本归原 Workspace，未知 token/价格明确未知；遥测 best-effort 不替代安全审计。具体原子机制与事件 schema 留给接受后的契约设计。

## 6. 三组逐状态纸面推演

以下均为设计审阅用的**预期结果**，没有对应 Memory 运行系统，不是执行通过记录。A、B 是不同员工，W、X 是不同 Workspace；S 表示受限服务身份。每行包含主体、来源、权限、审计及失败处理。

### 场景 A：个人偏好只在授权范围召回

| 状态/动作 | 主体与来源 | 权限与预期 | 审计与失败处理 |
| --- | --- | --- | --- |
| submitted → validated | A 在 W 明确提交“本项目报告先给摘要” P1 | Gateway 验证 A/W；private owner=A；不采集前后会话 | submit、scan；来源/敏感检查失败隔离 |
| working L1 → L3 | S 从 P1 生成偏好摘要 P2 | 保持 W/A 的私有范围和最早 TTL；ClientID=Codex 不作为 owner | derive、来源版本；伪造引用或越界输出不激活 |
| recall | A 的另一已授权客户端在 W 请求 P2；B 或 A 在 X 请求 | A/W 可读；B/W、A/X 均拒绝，即使 agent/client 标签相同 | recall/deny，无内容审计；身份/DLP/审计故障拒绝 |
| revision | A 改为“先列风险”，形成 P3 | 旧 P2 停用；同源冲突由 A 确认，新摘要保留修订链 | revise/resolve；并发旧版本写入不覆盖 P3，要求重读 |
| expired/deletion-pending | P1 到期或 A 删除 | P1/P2/P3 和缓存立即不可召回，迟到摘要不再写入 | expire/delete、清理失败；重试不续期，物理失败仍 deny |

### 场景 B：任务结果经审核晋升共享知识

| 状态/动作 | 主体与来源 | 权限与预期 | 审计与失败处理 |
| --- | --- | --- | --- |
| submitted → working | A/W 提交脱敏排障结果 R1 及源版本 D7 | 只提交选择材料；默认个人工作态，S 只读获准片段 | submit/derive；egress DLP deny 或 approval 未满足则无模型调用 |
| candidate | A 请求面向 W 运维组分享 C1 | 扫描、去重、冲突和 lineage；若 D7 私有，停留待源授权 | propose/check；无法查冲突则不假装通过 |
| reviewing → approved | 有发布权且非投稿者 B 审核 C1 摘要+R1/D7+目标 ACL | B 必须能读取所有来源；源共享授权者另行批准必要 ACL；批准绑定具体修订/范围 | approve/deny；内容/ACL/源版本变化使审批失效 |
| canonical-reference | Knowledge 发布方按审批执行 | 再验 B 的权限、源有效性和目标读者可读性；生成 K1，Memory 只存引用 | publish 与权威回执；失败/未知不伪报成功，幂等恢复 |
| recall / revise | 当前运维成员读取 K1；A 提交 R2 修正 | K1 带引用；R2 为新候选，不能覆写 K1；需新审核 | recall/revise；非目标成员或来源到期立即拒绝 |
| optional Skill proposal | A 希望把流程做 Skill | 另走 Registry 扫描/审核/签名；K1 批准不等于包已发布 | Registry 原有审计；失败无签名包、无自动安装执行 |

### 场景 C：删除原资料或员工退出后各层派生物停止召回

| 状态/动作 | 主体与来源 | 权限与预期 | 审计与失败处理 |
| --- | --- | --- | --- |
| active | A/W 私有 D1 → M1(L1) → M2(L2) → M3(L3)；另有 D1+D2 混合候选 C | 全链私有且同域；S 已排队下一次提取 | derive；缺任一 lineage 不激活 |
| deletion-pending（分支一） | 有删除权者删除 D1 | D1、M1–M3、C、相关正式版本引用与索引/缓存均不可召回/出站；混合物整体停用 | revoke/delete 可靠记录；停止在途释放，清理故障仍 deny |
| revoked（替代分支二） | 管理员移除 A/W 或禁用离职 A | A 对 W 所有访问拒绝；A 私有 D1 和 M1–M3/C 对所有人停用；有独立共享转归证据的企业源另按其现行 ACL | membership/identity revoke；后台重新鉴权失败即取消，不以 S 豁免 |
| narrowed（替代分支三） | 源授权者收窄原共享 D1 的 ACL，排除 B | B 不可读 D1 及各层摘要，其他人须逐源有效；不能从旧 K1/缓存得到片段 | acl-change/deny；ACL 服务未知时不释放内容 |
| stale worker / cleanup failed | S 持有撤销前输入，模型迟到；清理某索引失败 | 提交重验拒绝旧结果，失败索引也不能被召回；重试只清理 | discard、cleanup-failed、告警；失败可见、幂等重试无复活 |
| recomputed / purged | S 仅从仍合法 D2 重算；清理器最终成功 | 新 ID/修订、全新 lineage 与检查，若共享重新审批；原 D1 相关修订永不重开 | recompute/purge；备份恢复先重放删除事实，无法确认则不开读 |

## 7. 两种复用方式及成本判断

下表是静态依赖与安全边界推导的相对成本，**不是人日、性能或价格实测**。两路都必须完成 EAP 生命周期，封装不免除企业治理工作。

| 成本项 | 有限移植提取逻辑（推荐先实验） | 封装 MemoryCore 内部组件 |
| --- | --- | --- |
| 可保留价值 | L1 结构化提取、证据指向、批量去重 prompt 思路；先做单次无工具输出 | L0–L3、存储抽象、级联队列、场景管理已有实现 |
| 身份与隔离 | 直接消费 EAP Session/来源权限，仍需新领域校验 | 必须关闭外部入口/元数据管理，替换 caller IDs 权威；改 L2/L3 team+agent 范围，消除默认桶 |
| 存储与删除 | 新建有限派生处理逻辑；完整 lineage 与禁止复活仍需设计实现 | SQLite/文件/VDB 同步及后台状态适配 EAP 权威存储；不能仅靠 best-effort 删除或包外围过滤 |
| 模型/安全 | 适配既有模型治理，无工具执行；有限 prompt 的维护与来源许可成本 | 改 runner、工具 sandbox、自动 persona 更新、hooks、审计/遥测，确保没有旁路出站 |
| 运维升级 | 若用 Go 重写需维护语义差异与质量集；如复用 TS 仍须评审进程边界 | TS 组件运行环境、patch/上游升级回归、锁/队列恢复和多副本治理成本更大 |
| 质量与用量 | 单结果抽取+按需去重，模型调用较少；需证明有效信息保留 | 级联 L1/L2/L3 可能产生多轮抽取与重算；现成机制不证明更高质量或更低成本 |
| 适用条件 | 首批明确提交结果，范围小且希望保持单一权威 | 只有证明广泛 L2/L3 场景价值且可剥离身份/存储/工具边界后再考虑 |

模型预算按每次显式提交的输入/输出 token、去重候选数量、实际请求次数、重试/重算比例计入 Workspace；有预算上限、取消和队列积压观测。候选采纳率、人工审核时间、带来源的重复任务帮助率与误召回/越权率共同评价价值，不能仅数“存了多少条记忆”。固定脱敏数据集比较两路的质量、来源完整率、模型请求数、删除恢复复杂度和维护改动量后再估人日；本卡不安装或运行 MemoryCore，不虚构 benchmark。

## 8. 产品待决项与后续建议

| 真正需要产品/数据治理决定 | 推荐起点（尚未批准） | 另一选择及影响 |
| --- | --- | --- |
| 是否建设及首批价值 | 延续 P2；只做显式任务结果的隔离实验 | 延期合法；个人偏好先行则另定义本人编辑/续期体验 |
| 私有与共享默认值 | 默认 W 内私有，显式申请共享且来源授权可证明 | 默认共享增加误披露与审核负担，须明确接受与设计 |
| 自动捕获/自动 Prompt 注入 | 都关闭，显式提交和显式召回 | 任一开启需告知/退出/用途及第三方客户端约束，重新评审 |
| 跨 Workspace 个人记忆 | 禁止隐式迁移 | 允许时需双方授权、可迁移字段与删除责任；不靠相同 UserID 自动合并 |
| TTL 与清理承诺 | 审议 30/30/90 天示例、物理清理 SLA 和备份保留；不改变审计留存 | 更长留存增加成本/敏感暴露；更短降低长期价值 |
| 离职/源删除后的共享成果 | 保留有 Workspace 转归证据的合法源；源删除仍使依赖成果停用 | 希望“独立脱敏成果永久存续”需另行批准去依赖与合法留存规则 |
| 审核模式 | 人工且投稿/审核分离；置信度仅辅助 | 规则自动发布需独立准入、安全与误发布回滚设计 |

后续仅为**未批准的卡建议**，无新任务编号/ready 状态，不借本稿创建实施授权：

1. 产品决定与权限生命周期契约：固定场景、所有者、TTL、共享转归、审核权与撤销完成语义；验收逐项回放本稿三场景并完成独立安全评审。依赖产品批准及已接受的平台撤销/知识契约。
2. 有限抽取复用实验：钉版、脱敏输入、无工具/无自动捕获、结构化输出、来源与冲突验证；验收注入恶意材料不能改变权限，比较两路质量/成本，不发布生产服务。
3. 显式提交到私有召回垂直切片：仅在契约接受后实现；验收不同用户/Workspace/Client/实例、TTL、审批/DLP/审计故障及内容返回边界。
4. 晋升与生命周期切片：单一 Knowledge 发布回执、并发修订、旧审批拒绝、源删除/权限收窄、迟到模型、重试重启/备份恢复不复活；真实存储与故障注入覆盖全部派生物。
