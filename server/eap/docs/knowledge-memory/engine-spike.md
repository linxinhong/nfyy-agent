## Safety and recovery findings

1. **Production blocker — symlink escape in the engine file writer.** [`safe-path.ts`](../../experiments/tencentdb-knowledge/upstream/MemoryKnowledge/src/engines/wiki/ingest-v2/safe-path.ts) resolves path strings lexically, while [`commitCandidates`](../../experiments/tencentdb-knowledge/upstream/MemoryKnowledge/src/engines/wiki/ingest-v2/index.ts) later reads (`:247`) and writes (`:266-267`) that path. The script creates `<temp>/symlink-project/wiki/entities -> <temp>/outside`, preloads `<temp>/outside/escaped.md` with `OUTSIDE_SECRET_MARKER`, and passes candidate `wiki/entities/escaped.md`. It observes the marker in the model merge prompt and the outside file overwritten with no merge error. The isolated adapter does **not** reject this. A symlink swap race was **not** executed; a preflight symlink scan alone would remain racy. Production needs a confined file commit boundary using a fresh private directory plus no-follow/open-relative semantics or an equivalent race-safe writer, followed by regressions for pre-existing and swapped links before any source read or model merge. If generated pages are instead handed to EAP without upstream disk writes, the production adapter must still prove no path-based read/write escapes.
2. **Model and output governance remain EAP responsibilities.** The original [`llm.ts`](../../experiments/tencentdb-knowledge/upstream/MemoryKnowledge/src/engines/wiki/ingest-v2/llm.ts) constructs AI SDK providers from API keys. The spike-only runtime replacement disables that constructor and injects a deterministic stub. EAP must supply governed outbound Policy/DLP/audit/budget/cancel, redact source before egress, scan model output before index, and never pass an employee key or provider secret into the engine. The upstream failure dump writes raw model output under `_debug`; debug logging previews generated text. Both need removal or a safe bounded replacement before production use. Stub success gives no real-model generation-quality evidence.
3. **Derived storage is disposable only after EAP owns provenance and task state.** Upstream `module.ts` assembles SQLite store, `llm_binding` and Panel callbacks; its restart path marks interrupted tasks failed and restores indexes from its local directory. This copy calls neither module nor public routes. EAP must own source versions, authorization, job state, activation and tombstones in its existing authoritative store; stage generated files/CodeGraph SQLite under disposable, Workspace-confined paths; rebuild from an authorized source version or a pinned Git commit; verify source remains authorized just before activation. Model output is not generally deterministic, so recovering the *same* published Wiki version requires persisting an approved generated artifact or rebuilding a **new** generation. The experimental stub digest cannot establish real-model replay identity.
4. **Upstream public surface is unsuitable.** `middleware/auth.ts` permits `/tools/call` and several read endpoints without a service key and disables all auth when the key is empty. `module.ts` also routes via `service_id` bindings/Panel callback. None of these are an EAP employee authorization decision. The extracted functions were called in process; no upstream server was exposed.

Malformed FILE paths (`../secret.md`, `wiki/../secret.md`) and incomplete blocks were rejected by the parser; empty source failed explicitly. An injected model call was cancelled and rejected. These parser/cancellation checks do not close the symlink flaw or establish cancellation of a real provider call.

Propose extracting only the Wiki text-to-candidate component behind an EAP-owned in-process adapter, with server-derived Workspace/source/version and an injected governed model interface. Keep generated files and any CodeGraph SQLite as rebuildable cache; EAP PostgreSQL remains the sole authority for ACL, provenance, job state, active generation and deletion. Do not import `module.ts`, SQLite business store, Panel callback, `llm_binding`, auth middleware, source fetcher, or public API. Defer CodeGraph production use and graph protocol. A separate accepted ADR must choose any worker process boundary, internal identity/audience, deployment artifacts, license/NOTICE distribution, atomic publication/recovery, and no-follow file writer. The symlink writer defect, direct model path/raw failure dump, and source-version mapping are **hard gates** before TASK-061 production implementation; this report does not change TASK-061's `needs_arch_review` status.

## TASK-066 follow-up: memory-only Wiki execution boundary

This appendix describes a later **isolated** seam. The TASK-060 reproduction above remains historical evidence: the pinned `upstream/` copy, the reference repository and the runtime's legacy `extractSource`/`commitCandidates` file APIs are unchanged and unsafe. The new [`wiki-adapter.ts`](../../experiments/tencentdb-knowledge/wiki-adapter.ts) accepts server-owned source **bytes**, filename, Workspace, actor, SourceID, SourceVersion and a bounded text-range locator. It calls the pinned prompt builder, FILE parser, canonicalizer, source-frontmatter helper and merge function, while keeping old and new pages solely in a private `Map`. It never accepts a project root, reads an old page from a path, writes a candidate file, loads a disk template or calls the raw-output debug dump. This removes the demonstrated OS file read/write from the **candidate execution seam**; it does not repair the legacy file API.

Each session is bound after its first successful ingest to one Workspace/actor/source/version/filename tuple **and exact source SHA-256**. A different source version or different bytes requires a new session. Candidate records bind path and content bytes to that tuple, source SHA-256 and the server-supplied text range; the range is checked against the source bytes. Authority fields and locator are snapshotted before any model await, and one session serializes ingestion, rejecting a concurrent call or `clear()` while busy. Caller body/header isolation fields are rejected by the simulated server job builder. Cross-Workspace/source/actor reuse or changed bytes fail before any model call, so a private prior page cannot enter another scope's merge prompt. Failed parse, invalid path, invalid scope and model cancellation leave the candidate Map unchanged; `clear()` discards it. This is in-memory cleanup only, with no disk staging or external writer in this seam.

Before **and after** merge, the adapter rebuilds page frontmatter from a small content-field whitelist: `sources` is exactly the server-owned filename, and model-supplied `locked`, timestamp, Workspace/owner/source identity and other extra metadata are dropped. The merge model cannot mark a candidate locked or inject a forged source into the stored page. Both generation and merge receive the same AbortSignal. An abort-aware wrapper rejects promptly even if an injected model ignores that signal; it also checks for abort immediately before queued model dispatch. A late model result cannot commit the private Map. **Abandoning a noncooperative promise does not prove remote Provider egress stopped.** A production model bridge must implement real dispatch cancellation/join under the accepted platform revocation contract before declaring in-flight completion. The adapter imports canonicalization helpers from the legacy `index.ts`, so production packaging must extract those pure helpers or otherwise exclude the unsafe file API from the executable surface; this experiment proves calls, not a trimmed bundle.

`LOG_LEVEL=error npm run verify` retains the fixed Wiki v1/v2 page digests and CodeGraph fixture digests. It first demonstrates that the **legacy** file API reads `OUTSIDE_SECRET_MARKER` into a merge prompt and overwrites the outside file through an intermediate symlink. For the new adapter, the fixture plants both an existing intermediate link and an existing final-file link, then swaps an intermediate directory to a symlink inside a controlled model callback. The outside marker remains byte-identical and absent from captured model prompts; legitimate internal-page merge still occurs. A callback mutates the caller's authority and locator during model execution, but the returned candidate retains the original server snapshot. Concurrent/cross-scope attempts never reach the model. Forged `sources`/`locked`/timestamp/identity frontmatter is stripped at generation and merge. Traversal FILE output returns a safe error and an empty Map; cancellation during both generation and a deliberately noncooperative merge leaves the Map unchanged. A pre-dispatch abort test confirms zero model calls. The link tests prove only this OS-free adapter path: because it never dereferences candidate paths, the swap cannot create a TOCTOU window there. They are **not** evidence that a future disk writer is race-safe.
