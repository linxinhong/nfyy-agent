# 《20261010 下一步规划(1)》满足度基线

更新：2026-10-15。范围按原文的“眼下只做全所推广”，客户试用不计入当前验收。状态依据当前仓库源码与 [中心建设待办](yuanpu-server.md)，不是以页面示例或任务卡完成状态推定业务可用。原始材料位于用户提供的微信临时文件；本文保留 T 编号供后续逐项验收。

状态定义：“骨架”表示只有技术承载而无业务闭环；“局部”表示存在部分界面或本地实现，尚未通过原文场景；“未实现”表示本轮未找到对应的可运行闭环。后续开发每完成一个可验收场景再更新状态和证据。

| --- | --- | --- |
| T1.1 账号表、管理员开号与后台 | 局部；管理员后台已接入建号、设置密码、团队/角色管理、Key 发放与撤销；普通浏览器账号密码登录个人中心，桌面首次登录自动生成并保存 Key。通讯录导入和 Agent 批量开号未做 | 第一阶段。完成批量导入、Key 轮换与离职停用操作验收；不开放自主注册。 |

| T2.5 Meta 自审与评分 | 未实现 | 第三阶段。四项指标、样本门槛、版本对比和回滚；机器评分可以形成审核申请，自动固化组织 Skill 与原文“人审过才入库”存在冲突，上线前需固定发布规则。 |
| T2.6 Wiki UI 与审核队列 | 局部；网站工作台已接真实投稿、编辑和审核队列 API；桌面端按权限阅读已发布内容。属性化词条与链接导航仍未完成 | 第一阶段。补词条属性、关联与附件展示。 |
| T2.7 Listener/Worker 两级循环 | 未按原文场景验收 | 第三阶段。沿用本地 TS Agent，验证最小 Context、指针式材料、子任务、时限、用户补充与逐轮披露；不由 Go 网站重写模型循环。 |
| T2.8 按权限请求/下发及无状态子 Agent | 未形成中心到客户端闭环 | 第一阶段先提供认证和最小权限分发；第三阶段接本地子 Agent、日志事件和复取。原文“加密 JS 文件”不能阻止已授权终端读取明文，采用结构化数据、授权、限流与可撤回缓存，执行制品另走签名链。 |

新增的“企业内部分享平台”要求贯穿 T1、T2.2—T2.3、T2.6、T2.8 和 T3：浏览器网站承载资讯、Wiki 与 AI 能力目录，成员可投稿、审核、发布、按权限发现和使用。这是原规划“全所推广”的产品入口，不替代四库、两级 Agent 或后续功能。首个真实闭环及 A/B/C 跨团队验收见[中心建设待办](yuanpu-server.md#企业内部分享的首版闭环)。

《下一步规划(3)》的认证方案已按 2026-10-15 最新要求调整为浏览器账号密码与桌面设备 API key；权限按角色配置动作与范围；作者确认后交独立审核人；运行日志与数据文件使用分开的上传接口。首版后端、SDK 和网站工作台已接通，日志只允许结构化元数据，数据上传限 2 MiB 且仅上传者下载。仍需桌面端实际接入上传、对象存储/扫描、团队附件发布规则和生产部署验收。
